# Инструкции для Codex

Это статический многостраничный сайт: HTML-шаблоны с `@@include`, SCSS и vanilla JavaScript. Здесь нет компонентного framework и нет `props`: повторное использование происходит через partial-файлы, BEM-подобные CSS-классы и data-атрибуты.

Перед любой задачей по вёрстке выполни этот порядок:

1. Разбери требования и прочитай [каталог компонентов](docs/component-catalog.md), [паттерны страниц](docs/page-patterns.md) и, если затронут визуал, [дизайн-систему](docs/design-system.md).
2. Найди подходящий блок или похожую страницу; затем обязательно проверь его настоящую разметку и SCSS в `src`.
3. Переиспользуй существующий компонент в первую очередь. Если он почти подходит, сначала оцени безопасное расширение существующего API классов/разметки.
4. Не создавай дублирующие UI-компоненты и не переписывай существующие без необходимости. Новая страница должна сначала сверяться с аналогами из `docs/page-patterns.md`.
5. Используй существующие токены, utility-классы, assets и соглашения из `docs/design-system.md`; соблюдай структуру, импорты и сборку из [architecture.md](docs/architecture.md).
6. Не добавляй зависимости без реальной необходимости. Не воспринимай закомментированные модули в `src/js/app.js` как включённую функциональность.
7. Если новый блок действительно стал переиспользуемым, создай/выдели его в принятом формате и обнови `docs/component-catalog.md` и при необходимости `docs/page-patterns.md`.
8. Запусти доступную релевантную проверку (`npm run lint` для JS, `npm run build` для интеграционной проверки) и сообщи результат.

Читайте [architecture.md](docs/architecture.md) перед изменением структуры, entry point или сборки. Документация описывает только подтверждённое исходниками; при расхождении с кодом приоритет у кода, а документ следует актуализировать.
